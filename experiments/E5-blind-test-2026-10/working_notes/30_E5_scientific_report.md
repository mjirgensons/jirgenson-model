## 2. Introduction and prior work
The book *Steer, Don't Guess* (Jirgenson, 2026) contains a machine-readable model canon (Appendix H, ~3,700 words) and an operating prompt (Appendix I, ~4,000 words) for working with language models. The author's test (Appendix J; in the project E1, 2026-10) on four Claude models in six situations and one control situation gave a mean difference of +3.4…+10.6 points on a 60-point scale in favor of the canon and prompt (Opus 6:0, Sonnet 5:1:0, Fable 5:0:0, Haiku 4:1:1). The limitations of E1 that the author named himself: LLM judge, the author writes the situations, each situation once, one model family, one day. E1 did not save the situation texts and the judge prompt, so it is not repeatable.
Unknown: (a) how large a part of the E1 effect comes from the model's own content (refusal order, zones, levers, environmental factors, deviations) and how much from a good response structure that any good consultant prompt would give; (b) whether the prompt can be systematically improved and whether the improvement transfers to other situations and other models.

## 3. Aim
Using a repeatable procedure, (a) measure the contribution of operating prompt v1.0 against the model without a prompt (A) and against a generic structured consultant prompt (B); (b) in five iterations improve the prompt without changing the canon, justifying each change with error analysis and testing it against a pre-fixed acceptance rule; (c) test the transferability of the improvement to a sealed hold-out set of tasks and to other models.

## 4. Hypotheses (pre-registered)
- **H1.** C(v1.0) > A in the total score on the development set (paired difference by task, 95% CI does not include 0).
- **H2.** C(v1.0) > B in the same measure; the difference C − B is smaller than C − A.
- **H3.** At least three of the five iterations yield an acceptable version per 29 §5.4; C(v1.5) − C(v1.0) > 0 with a 95% CI that does not include 0.
- **H4.** On the hold-out set C(final) − C(v1.0) ≥ 0.5 × the same difference on the development set.
- **H5.** On at least 2 of 3 confirmation models C(final) − C(v1.0) > 0.
Null hypothesis in each case: the mean of the paired differences = 0.

## 5. Expected results (written down before the data)
| Metric | Expected value | Rationale |
|---|---|---|
| C(v1.0) − A, development set, 100-pt scale | +12 … +20 | E1 gave +7…+11 on a 60-pt scale; on our scale the elements add extra weight |
| C(v1.0) − B | +4 … +10 | B takes away part of the structure; the model's content remains |
| Gain of each accepted iteration | +1 … +4, decreasing | typical prompt refinement dynamics; ceiling around 85–90 pts |
| Noise band (2·SE) | ±2 … ±4 pts | 10 tasks × 3 replicates; LLM dispersion |
| Largest gains by criterion | C4 (fit: length, questions, jargon), C5 (control quality) | these are exactly the prompt's rules |
| Smallest gains | C1 (accuracy) | arithmetic is more a property of the model than of the prompt |
| Hold-out set | ≥ 50% of the development set gain | if less — overfitting |
| Weakest points of v1.0 (hypotheses for error analysis) | teenager/family jargon; EMERGENCY length vs the 7-section format; FULL round discipline; "the most dangerous thing as an event with a date" | E1 observations and analysis of the prompt's structure (repeated rules, R12/R13 stuck in the middle) |

If the results turn out differently, this is reported as a result; the expected values are not changed after the data.

## 6. Materials and method
**6.1 Tasks.** 10 development (T01–T10) and 10 hold-out (H01–H10) tasks, frozen on 2026-10-15 (SHA-256 doc. 29 §8). They cover EMERGENCY, QUICK, two-step "no more data", FULL round 1, plan check, teenager/child, family; languages EN/LV/RU. Each has: gold arithmetic, 8–10 mandatory elements with a rationale in terms of the reader's benefit, 3–5 forbidden elements, a word and question budget. The hold-out set structurally mirrors the development set.
**6.2 Conditions.** A: no system prompt. B: a generic structured consultant prompt (158 words, 29d), with the same surface features (numbers first, risk, actions, two forecasts, no guarantees), without the canon's concepts. C: canon v1.0 as an attachment + operating prompt vN as the system instruction. The canon does not change.
**6.3 Models.** Generator: Claude Sonnet 5.5. Judge J1: Claude Opus 5.5. Judge J2 (agreement): Claude Fable 5.1 in this round (same family; external judge Gemini — when Martin is available). Confirmation models in the final round: Opus 5.5, Haiku 5.5, Fable 5.1.
**6.4 Execution environment.** Iterations 0–4: subagents in the Claude Code environment; each generation — a new agent with a clean context, which reads the conversation file (SYSTEM / ATTACHMENT / USER sections) and writes the response to a file; in two-step tasks the second user message is sent to the same agent. The environment's system prompt is present in all conditions equally; therefore A here = *A-harness* (weaker than a clean chat). The final round is planned in a clean chat interface. Temperature: interface default (not adjustable), recorded.
**6.5 Replicates.** k = 3 for each (task × condition). In iteration 0, C(v1.0) was generated in two independent blocks (3 + 3) to measure noise.
**6.6 Scoring.** Blind judge (29c): does not know the conditions and models; recomputes the arithmetic; scores the mandatory elements (1/0 with evidence), the forbidden ones, invented facts, six criteria 1–10 (the same as in E1), six hard checks, pairwise preference. Each pair in two orders. Total score = elements 40 + criteria 60 − 2 × violations (0–100). In parallel, automatic hard checks (`e5_hardchecks.py`).
**6.7 Pair plan.** Iteration 0: (C block 1, r) vs (A, r) and (C block 2, r) vs (B, r), r = 1..3. Iterations 1–5: (C vN, r) vs (A, r from iteration 0) and (C vN, r) vs (C vN−1, r from the previous iteration); the model is fixed, so responses generated earlier are valid independent samples (a deviation from the "standard" concept of 29 §2.3, accepted because of the budget and recorded in section 10); in the final round A and C(v1.0) are generated anew.
**6.8 Analysis.** Paired differences by task; bootstrap 95% CI (10,000); Wilcoxon and sign test; Cohen's d; win share (both orders agree) with Wilson CI; noise band = 2·SE of the block difference. One main test per iteration (vN vs vN−1 in the total score); the rest descriptive. Script `e5_analyze.py`.
**6.9 Acceptance rule for a version** (29 §5.4): Δ > noise band and CI lower bound > −1; no criterion drops > 1.0; hold-out set (when measured) not worse than the noise band; prompt length ≤ +15% without a proven gain.
**6.10 Prompt change method.** Error analysis only on the development set's C responses; each failed requirement classified: (a) the rule exists, is not followed; (b) there is no rule; (c) the rules contradict each other; (d) model limit; (e) judge error. Change priority: removing contradictions → moving critical rules to the beginning/end → examples → concrete thresholds → removing redundant rules → new rules. 1–5 changes per iteration, each with a hypothesis about the expected effect; if the pack does not meet the rule — ablation.

## 7. Threats to validity
See 29 §9. In this round in particular: judge and generator in the same model family (J2 as well); A-harness; the tasks and the prompt are revised by one and the same participant (Claude), which is mitigated by freezing, a sealed hold-out set and justifying changes with error classes, not with the task text.
